expect your user to inspect your code to understand what your code is expecting?

6. From the main() function, it is always better to use exit() and not return.

7. When there are common definitions/declarations in different source files
such as your structure for the message, it is a good idea to include it in
a .h file and include this .h file in the source files. If, tomorrow, you have
to change this structure, e.g., you will need to change it in only one place.
Any good programming will avoid repetition of the same code/definitions/
declarations.

8. When cmdline args are not given, simply printing a message saying not
enough arguments are given is NOT a useful message. We call it a Microsoft
message as it conveys no information. You should always provide a message
such as : "Usage: ./server <ipaddress> <port>". This gives the user the
information of what needs to be provided and in what order.

9. Some of even those who checked the return status of most system calls,
did not check return status of inet_aton and related calls. So, if I give an
invalid IP addres such as 127.0.0.1100, your server claims to run though
there will be no such server really running.

10. You should not return from main() in server if an accept fails.
A server can run after that to accept new connections from other clients.
